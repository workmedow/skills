# WorkMedow

Use the human-selected connection and space or actual project. Within a selected writable space, use an existing matching project or create a real product/repository project when the requested work needs one; no separate project approval is required. Once that context is established, apply this workflow to subsequent work requests there; the human need not repeat “WorkMedow.” Do not adopt unrelated conversations, move work to another space without authorization, impersonate another Agent, or copy another conversation's session. If the intended work or space is unclear, ask for that missing context rather than inventing it.

A connection authorizes one or more spaces. A space is the only access boundary: its grant covers every current and future project in that space. Select one actual project for each project-scoped operation; no project is inferred from list order. Capability, space and project discovery may run before choosing that target. In a writable authorized space, an Agent may create a real product or repository project without separate project approval or an existing project session. Do not create projects merely to mirror internal planning. If the human explicitly requests work in A and B in this conversation, keep a separate business session and goal context for each project. Never use A's session for B or treat access as permission to copy work between them. Legacy project credentials keep their original limit until the human explicitly reauthorizes spaces.

Choose the available connection in this order: WorkMedow MCP tools; an already installed `workmedow` CLI with a command tool; an HTTP tool that already injects authorized credentials securely. An authenticated HTTP tool can read the project without installing the CLI. A skill file alone cannot make network requests. If none is available, ask the human to complete the connection guide. Do not install arbitrary software, print credentials, edit unrelated host configuration, or grant yourself broader access.

For actual work, read [references/workflow.md](references/workflow.md) for the shared lifecycle, tool names and payloads. Read [references/cli.md](references/cli.md) for CLI transport and recovery, or [references/http.md](references/http.md) for direct HTTP. Direct HTTP needs host-owned durable write protection or must remain read-only. No token or machine-specific path belongs in this skill.

Choose the mode before creating anything:

- **Connection check or strictly read-only request:** read capabilities, authorized spaces/projects and the explicitly requested non-consuming project information, such as context, tasks or activity. Do not create a project, session, task, message or receipt. An existing verified session of this conversation may be used for the non-consuming queue; otherwise explain that its queue needs a session. `doctor` verifies access, not task recording or external execution.
- **Work requested in the selected project:** confirm project `write` capability, reuse or open this conversation's business session, then reuse an explicitly identified task or create one goal before substantial work. Record the start, significant progress and verified result. Keep internal planning, tool calls and subagents in the host. Do not require the human to repeat a logging instruction for each follow-up.

Use latest versions for state changes and read back the saved outcome. Report the actual task ID and `done` or `in_review` status; human acceptance remains separate. A task created by this Agent is self-assigned and needs no extra claim. Do not take another Agent's task or bypass an existing session claim.

Ask a structured input request only for an actual decision or missing input. Answers and cancellation do not automatically resume blocked work; reread the task and explicitly resume when legal. Preserve human review requirements. Share only the goal, useful progress and result the human intended for this project, not private prompts or credentials.

If writes are unavailable or rejected, say which record was not saved; do not claim that WorkMedow was updated. For work whose shared record is required, resolve that gap before substantial untracked work. Unknown write results must retain the original operation, payload, key and versions. Confirm the original result or explicitly recover it before another conflicting write in that space/project partition; reconnecting must not resend automatically. Explicitly requested work in another authorized project may continue with its own session and goal, while keeping the original unresolved record visible. Switching projects cannot replay, retarget or bypass that original operation.

Assignments, messages, answers, ACKs and this skill do not grant deployment, purchase, sending, or other external authority. Follow the human's actual request and this host's permission rules. WorkMedow does not run models or wake idle hosts.
